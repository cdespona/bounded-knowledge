# Research: rendering approach for a stdlib-only, local-only catalog view

Ticket: #21 (Wayfinder research). Researched 2026-11-16. This is input to a later human
decision, not a decision record. Status words follow the repository convention:
**confirmed** means a primary source supports the claim, **inferred** means it is
reasoned from confirmed facts, and **unknown** means it was not established.

## Answer

Recommended: a **static multi-page site generated by Python stdlib code**, with **graphs
drawn as SVG in Python** and, optionally later, **one vendored and pinned Cytoscape.js**
for the interactive ecosystem map.

1. **Pages.** Generate plain HTML files from the validated catalog JSON with small
   Python render functions. Pass every catalog string through `html.escape` at the point
   where it is inserted. `string.Template` can hold the page skeleton, but it does **no**
   HTML escaping, so escaping must be enforced in the render helpers (confirmed). Write
   files in sorted order with fixed formatting so the output is byte-stable for a given
   catalog.
2. **Opening.** Make `file://` the default. Inline all data in the page, either as HTML
   or as a `<script type="application/json">` block, so nothing calls `fetch()`.
   Browsers often block `fetch` and cross-file loads from `file://` (confirmed, MDN).
   `python3 -m http.server --bind 127.0.0.1 --directory site/` is an optional fallback,
   never a requirement. Python documents that it binds to **all interfaces** by default
   and follows symlinks (confirmed).
3. **Graphs.** For the per-application neighborhood graph and the impact paths, compute
   a simple deterministic layout in Python (layered or radial; at most a few dozen
   nodes) and emit SVG with `<a href>` links to entity anchors. This needs no JavaScript,
   is deterministic, and is safe because the text goes through the same escaping.
4. **Whole-ecosystem map (about 50 to 500 entities).** If static SVG becomes unreadable,
   add **Cytoscape.js** as a vendored, pinned, checksummed file. It has **no runtime
   dependencies**, is MIT-licensed, draws on canvas, and has no published security
   advisories (confirmed). Use its `preset` layout with positions computed in Python, so
   the generated page stays deterministic. Show labels and details with `textContent`
   only.
5. **Do not use** a CDN (it needs the network when the page is viewed), Mermaid as the
   renderer for catalog-driven graphs, or Graphviz as a required step.
   - Mermaid: the bundle is about 5.5 MB and has many dependencies. It turns model-written
     text into another grammar that has its own injection history. Its default
     `maxEdges` is 500, which is the top of our target range (all confirmed).
   - Graphviz: an external EPL-2.0 binary, which breaks "stdlib-only" unless it stays
     optional.

Main trade-off: the stdlib SVG path costs the most to build, because we write a small
layout routine. In return it has the lowest dependency, safety and determinism risk. The
Cytoscape path gives better interactivity (pan, zoom, filter by relationship type and
confidence) for one reviewed 443 KB dependency.

## Evidence

### Python standard library

- `string.Template` does `$` substitution only. Its only escaping is `$$` for a literal
  `$`, and it says nothing about HTML. The docs name i18n as its main use case.
  `substitute` raises on missing keys and `safe_substitute` does not. Use
  `substitute` so a missing field fails the build. Confirmed:
  <https://docs.python.org/3/library/string.html#template-strings>
- `html.escape(s, quote=True)` converts `&`, `<`, `>`, `"` and `'`, which makes text
  safe in element content and in quoted attributes. Confirmed:
  <https://docs.python.org/3/library/html.html#html.escape>
- Embedding JSON in a `<script>` block: `json.dumps` does not escape `<`, so a catalog
  string that contains `</script>` would end the block early. Replace `<`, `>` and `&`
  with `<`, `>` and `&` after `json.dumps(..., sort_keys=True)`.
  Inferred from the HTML spec's restrictions on script content:
  <https://html.spec.whatwg.org/multipage/scripting.html#restrictions-for-contents-of-script-elements>
- `http.server` facts, all confirmed at
  <https://docs.python.org/3/library/http.server.html>:
  - It is "not recommended for production. It only implements basic security checks."
  - "By default, the server binds itself to all interfaces"; `--bind 127.0.0.1`
    restricts it.
  - `SimpleHTTPRequestHandler` "will follow symbolic links", so it can serve files
    outside the directory.
  - `--directory` exists since 3.7, which is within our 3.9+ floor.

### `file://` versus a local server

- MDN, confirmed:
  <https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Tools_and_setup/set_up_a_local_testing_server>
  - Some browsers, including Chrome, will not run async requests from a local file.
  - Browsers commonly treat `file://` resource requests as cross-origin, which can
    trigger CORS errors.
- ES module scripts load in CORS mode, so `<script type="module">` from `file://` is
  expected to fail the same way. Inferred. Classic `<script src="vendor/x.js">` works
  from `file://` (inferred from common practice; verify per browser, see open
  uncertainties).
- Consequence: inline the data and use classic scripts. With that, `file://` works and
  no server is needed.

### Content Security Policy

- CSP can be delivered in a `<meta http-equiv="Content-Security-Policy">` element.
  `default-src` is the fallback for other fetch directives, and `'none'` blocks a
  resource type completely. Confirmed:
  <https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy>
- A meta policy such as `default-src 'none'; img-src 'self' data:; style-src 'self';
  script-src 'self'` with `connect-src 'none'` adds defense in depth: even injected
  markup cannot make network calls or run inline script. Inferred. How browsers resolve
  `'self'` under `file://` is unknown (see open uncertainties).

### Catalog shape (this repository)

- Catalog ids match `^[a-z0-9][a-z0-9-]*$`, so they are safe as file names and URL
  fragments without encoding. Confirmed: `schemas/landscape-catalog.schema.json`
  (`$defs.id`).
- Repository evidence carries `repositoryId`, `commit` (40 to 64 hex characters),
  `path`, optional `lines` (`N` or `N-M`) and an optional `observationId`. Confirmed:
  `$defs.repositoryEvidence`. Every claim's assessment holds separate `evidence` and
  `counterevidence` arrays, plus `missingEvidence`. Confirmed: `$defs.assessment`.
- `schemas/source-topology.schema.json` `$defs.repository` holds only `id` and `kind`.
  There is **no remote URL**, so the evidence drawer can link inside the site and show
  `repositoryId@commit:path#Lx-y` as text. Linking out to a code host would need a new,
  deliberately reviewed field. Confirmed.
- `docs/initiative/landscape-plan.md` ("Local website", "Milestone 6") requires stable
  deep links from claims to evidence and disposable website indexes. Option A meets
  both: one page or anchor per id, and the site regenerated under a disposable output
  directory.

- The latest releases above are under two weeks old. If the project adopts a minimum-age
  rule for pins, pick the newest release that satisfies it and record its SHA-256 in the
  repository.
- **Cytoscape.js**: "No external dependencies"; renders on canvas; built-in layouts
  include `grid`, `circle`, `concentric`, `breadthfirst`, `cose` and `preset`. The
  `preset` layout places nodes at supplied positions, and the graph serializes to and
  from JSON. The core and first-party extensions are MIT. Confirmed:
  <https://js.cytoscape.org/>. No published security advisories, confirmed:
  <https://github.com/cytoscape/cytoscape.js/security/advisories>
- **vis-network**: canvas rendering, hierarchical layout, and a seed you can reuse
  through `layout.randomSeed`, confirmed:
  <https://visjs.github.io/vis-network/docs/network/>
  - Node `title` "can be an HTML element or a string containing plain text".
  - `font.multi: true | 'html'` makes the label "interpreted as html".
  - Both confirmed at <https://visjs.github.io/vis-network/docs/network/nodes.html>.
    These options must stay off for model-written text.
  - No published advisories, confirmed:
    <https://github.com/visjs/vis-network/security/advisories>
- **D3**: a general visualization toolkit. A typed, filterable graph view would be our
  own code built on `d3-force`, `d3-zoom` and similar modules (inferred). No published
  advisories, confirmed: <https://github.com/d3/d3/security/advisories>
- **Mermaid** configuration, confirmed:
  <https://mermaid.js.org/config/schema-docs/config.html>
  - `securityLevel` defaults to `strict`: "HTML tags in the text are encoded and click
    functionality is disabled".
  - `loose` and `antiscript` allow HTML in text and enable clicks.
  - `sandbox` renders in a sandboxed iframe.
  - `maxTextSize` defaults to 50000 and `maxEdges` to 500.
  - `deterministicIds` defaults to `false`; otherwise ids are based on the current date.
  - Clickable evidence links would therefore need a less strict mode, or links added
    after rendering.
- **Mermaid advisories**: GitHub lists 10 advisories on the first page, confirmed:
  <https://github.com/mermaid-js/mermaid/security/advisories>. Among them:
  - architecture `iconText` XSS (Critical, 2025-08-19)
  - classDef HTML injection in state diagrams (2026-05-11)
  - several CSS-injection, prototype-pollution and DoS issues (2026-05-11 and
    2026-08-04)

  This is an attack surface that grows with diagram features, and we would feed it
  model-written text.
- **Graphviz**: EPL-2.0, confirmed: <https://graphviz.org/license/>. Its download page
  lists 16.1.1 and Homebrew/apt packages (third-party), confirmed:
  <https://graphviz.org/download/>. It is an external native binary, so it is not
  stdlib. Inferred: it fits only as an optional "pretty layout" step with a stdlib
  fallback, and its SVG output would itself need the same escaping discipline for
  labels.

### Readability at about 50 to 500 entities (inferred)

- The catalog defines 7 relationship types and 6 entity kinds. A full map of 500 nodes
  is not readable as one static picture. The readable patterns are:
  - focused subgraphs per application or context, drawn as static SVG
  - an interactive overview with filters for type and confidence and with
    pan and zoom, using Cytoscape or vis-network
- Mermaid's default `maxEdges: 500` caps the top of the range unless it is raised, and
  raising it increases layout time.
- Precomputing positions in Python and reusing them in both the SVG and the Cytoscape
  `preset` layout keeps both views consistent and deterministic.

## Open uncertainties

- **CSP under `file://`**: whether `script-src 'self'` allows a sibling
  `vendor/cytoscape.min.js` loaded from `file://` in current Chrome, Firefox and Safari
  is unknown. Test before relying on it. The fallback is to inline the vendored script
  and allow it by `sha256-` hash.
- **Classic scripts from `file://`**: inferred to work in all three engines; not
  verified per browser in this research.
- **Layout effort**: the cost of a "good enough" stdlib layered layout with crossing
  reduction for the neighborhood views is unknown. Prototype it with synthetic
  fixtures from `examples/` before choosing between B and C for the overview.
- **Cytoscape determinism without `preset`**: whether `cose`/`breadthfirst` are
  reproducible across runs was not established. The recommendation avoids the question
  by using `preset`.
- **Rendering through pinned headless engines**: not evaluated (for example `@viz-js/viz`
  3.31.0, MIT, a WebAssembly build of Graphviz, or Cytosnap). They would need Node or a
  WebAssembly runtime at build time, which conflicts with stdlib-only generation.
- **Accessibility**: canvas graphs (Cytoscape, vis-network) are not readable by screen
  readers. Every graph view should have an equivalent HTML table or list of edges.
  Option A provides this, but the requirement is not yet in the plan.
